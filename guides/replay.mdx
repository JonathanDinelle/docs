---
title: "Test with replay"
description: "Run your agent against recorded traces in your tests, with no live LLM calls."
---

`VevalTestSdk` is a test double for `IVevalSdk`. It [replays](/concepts/replay) a recorded trace so your agent code runs with mocked LLM responses: deterministic, fast, and free.

Unlike calling `VevalSdk` directly with a trace, `VevalTestSdk` guarantees no live LLM fallthrough. If a step name doesn't match the recorded trace, it throws immediately.

## Setup

<CodeGroup>
```csharp C#
// 1. Load a production trace
var trace = await veval.GetTraceAsync("tr_4ec4e79c5d03...");

// 2. Create the test double
var testSdk = new VevalTestSdk(new VevalOptions { ApiKey = "YOUR_API_KEY" })
    .WithReplay(trace);

// 3. Inject into your service (IVevalSdk interface)
var service = new MyAgentService(testSdk, claude);

// 4. Call normally — no live LLM
var result = await testSdk.RunAsync("my-agent", service.ExecuteAsync);
```

```python Python
# 1. Load a production trace
trace = await veval.get_trace_async("tr_4ec4e79c5d03...")

# 2. Create the test double
test_sdk = VevalTestSdk(VevalOptions(api_key="YOUR_API_KEY")).with_replay(trace)

# 3. Inject into your service
service = MyAgentService(test_sdk, anthropic)

# 4. Call normally — no live LLM
result = await test_sdk.run_async("my-agent", service.execute_async)
```

```javascript Node
// 1. Load a production trace
const trace = await veval.getTraceAsync("tr_4ec4e79c5d03...");

// 2. Create the test double
const testSdk = new VevalTestSdk({ apiKey: "YOUR_API_KEY" }).withReplay(trace);

// 3. Inject into your service
const service = new MyAgentService(testSdk, anthropic);

// 4. Call normally — no live LLM
const result = await testSdk.runAsync("my-agent", (ctx) => service.execute(ctx));
```
</CodeGroup>

<Note>
  `VevalTestSdk` still reports traces and scenario results to the dashboard, so runs count in your history.
</Note>

## In a test project

<CodeGroup>
```csharp C#
[Fact]
public async Task Agent_ReturnsExpectedOutput()
{
    var trace = LoadFixture("trace_prompt_caching.json");  // or fetch from API

    var testSdk = new VevalTestSdk(new VevalOptions { ApiKey = TestApiKey })
        .WithReplay(trace);
    var service = new MyAgentService(testSdk, /* mock claude */);

    var result = await testSdk.RunAsync("my-agent", service.ExecuteAsync, input: "test input");

    Assert.Equal("success", testSdk.LastStatus);
    Assert.Contains("caching", result);
}
```

```python Python
import pytest

async def test_agent_returns_expected_output():
    trace = load_fixture("trace_prompt_caching.json")  # or fetch from API

    test_sdk = VevalTestSdk(VevalOptions(api_key=TEST_API_KEY)).with_replay(trace)
    service = MyAgentService(test_sdk)

    result = await test_sdk.run_async("my-agent", service.execute_async, "test input")

    assert test_sdk.last_status == "success"
    assert "caching" in result
```

```javascript Node
import { VevalTestSdk } from "@veval/sdk";

test("agent returns expected output", async () => {
  const trace = loadFixture("trace_prompt_caching.json");  // or fetch from API

  const testSdk = new VevalTestSdk({ apiKey: TEST_API_KEY }).withReplay(trace);
  const service = new MyAgentService(testSdk);

  const result = await testSdk.runAsync("my-agent", (ctx) => service.execute(ctx), "test input");

  expect(testSdk.lastStatus).toBe("success");
  expect(result).toContain("caching");
});
```
</CodeGroup>

## Strict mock mode

If your agent calls `TrackStepAsync` with a step name that isn't in the recorded trace, `VevalTestSdk` throws:

```
InvalidOperationException: Replay mode: no mock output for step 'new_step'.
Available steps: classify, answer.
This would have made a real LLM call.
```

This catches regressions where code changes add new LLM calls that weren't in the original trace.

A step that failed in the recorded run fails again: replay throws a `RecordedStepException` (`RecordedStepError` in Python and Node) with the recorded error message, so a retry or fallback runs as it did in production. To test failures the recording doesn't contain, see [Test failure paths](/guides/failure-paths).

The opposite fails too: if the agent never calls a step the trace recorded, the replay fails with

```
Replay never called 1 recorded step(s) from trace tr_...: 'visit_portal' (recorded step 2).
```

When several recorded steps share a name, each call is served the one with an identical input, falling back to the next unused one in recorded order. See [how calls are matched](/concepts/replay#how-calls-are-matched-to-the-recording).

A call whose input differs from every recording of that step is reported, not failed. Read the report from the replay result:

<CodeGroup>
```csharp C#
var result = await testSdk.ReplayAsync(trace, service.ExecuteAsync, new ReplayOptions { MockLlmResponses = true });

foreach (var b in result.Fidelity!.Bindings.Where(b => b.Kind == ReplayBindingKind.Diverged))
    Console.WriteLine($"{b.StepName}: recorded {b.RecordedInput}, now {b.ActualInput}");
```

```python Python
result = await test_sdk.replay_async(trace, service.execute, ReplayOptions(mock_llm_responses=True))

for b in result.fidelity.bindings:
    if b.kind == "diverged":
        print(f"{b.step_name}: recorded {b.recorded_input}, now {b.actual_input}")
```

```javascript Node
const result = await testSdk.replayAsync(trace, (ctx) => service.execute(ctx), { mock_llm_responses: true });

for (const b of result.fidelity.bindings.filter((b) => b.kind === "diverged"))
  console.log(`${b.step_name}: recorded ${b.recorded_input}, now ${b.actual_input}`);
```
</CodeGroup>

## Live replay

To test a prompt change against a recorded trace, replay live: steps recorded as `llm` call the model, and every other step returns its recorded output, so tools never reach a real system. See [Live replay](/concepts/replay#live-replay) for the rules.

<CodeGroup>
```csharp C#
var result = await testSdk.ReplayAsync(trace, service.ExecuteAsync, new ReplayOptions
{
    LiveModelSteps = true,
    Assertions     = [TraceAssert.OutputContains("overdue")],
});
```

```python Python
result = await test_sdk.replay_async(trace, service.execute, ReplayOptions(
    live_model_steps=True,
    assertions=[TraceAssert.output_contains("overdue")],
))
```

```javascript Node
const result = await testSdk.replayAsync(trace, (ctx) => service.execute(ctx), {
  live_model_steps: true,
  assertions: [TraceAssert.outputContains("overdue")],
});
```
</CodeGroup>

Trace-backed scenario items run with `VevalSdk` replay live by default; `VevalTestSdk` keeps them mocked.

### When the model takes another path

If a tool step is called with an input the recording doesn't have, or a step has no recording left, the live replay stops there and is inconclusive rather than serving the model a recording from another path. Check `Outcome` to tell it apart from a failure, and use step rules for steps whose input doesn't matter. See [When the run leaves the recording](/concepts/replay#when-the-run-leaves-the-recording) for the rules.

<CodeGroup>
```csharp C#
var result = await testSdk.ReplayAsync(trace, service.ExecuteAsync, new ReplayOptions
{
    LiveModelSteps = true,
    Assertions     = [TraceAssert.OutputContains("Booked")],
    StepRules =
    {
        // Narration follows the model's wording and doesn't change the page.
        ["set_screen_capture_reasoning"] = new ReplayStepRule { MatchOnNameOnly = true },
        ["page_snapshot"] = new ReplayStepRule { IgnoreInputFields = new HashSet<string> { "reasoning" } },
    },
});

if (result.Outcome == ReplayOutcome.Inconclusive)
    Console.WriteLine(result.Inconclusive!.Message); // the step, and the recorded and actual input

Assert.True(result.Passed, result.Summary); // fails with e.g. "inconclusive at step 3 'fill' — ..."
```

```python Python
result = await test_sdk.replay_async(trace, service.execute, ReplayOptions(
    live_model_steps=True,
    assertions=[TraceAssert.output_contains("Booked")],
    step_rules={
        # Narration follows the model's wording and doesn't change the page.
        "set_screen_capture_reasoning": ReplayStepRule(match_on_name_only=True),
        "page_snapshot": ReplayStepRule(ignore_input_fields={"reasoning"}),
    },
))

if result.outcome == "inconclusive":
    print(result.inconclusive.message)  # the step, and the recorded and actual input

assert result.passed, result.summary  # fails with e.g. "inconclusive at step 3 'fill' — ..."
```

```javascript Node
const result = await testSdk.replayAsync(trace, (ctx) => service.execute(ctx), {
  live_model_steps: true,
  assertions: [TraceAssert.outputContains("Booked")],
  step_rules: {
    // Narration follows the model's wording and doesn't change the page.
    set_screen_capture_reasoning: { match_on_name_only: true },
    page_snapshot: { ignore_input_fields: ["reasoning"] },
  },
});

if (result.outcome === "inconclusive") console.log(result.inconclusive!.message); // the step, and the recorded and actual input

assert.ok(result.passed, result.summary); // fails with e.g. "inconclusive at step 3 'fill' — ..."
```
</CodeGroup>

`Passed` is false for an inconclusive replay, so a test that asserts it fails instead of reporting a pass the replay can't back up. `Summary` (`summary`) puts the result on one line, e.g. `inconclusive at step 3 'fill' — 2/5 recorded steps used, 0 diverged but served, 1 live, left the path`, and the replay's trace has status `inconclusive` rather than `error`. For a scenario, pass the rules in `ScenarioOptions` to `RunScenarioAsync` (`StepRules`; `step_rules` in Python and Node) or set them on one item.

## Test tool changes

Mocked and live replays serve tool steps from the recording, so a changed tool never runs: a formatter that now returns the wrong price still passes. A **tool-live replay** inverts live replay. Steps recorded as `tool` run for real, and every other step, model steps included, comes from the recording. Because the model's path is the recorded one, each tool is called with its recorded input, and its new output is compared with the recorded output. A difference fails the replay.

<CodeGroup>
```csharp C#
var result = await testSdk.ReplayAsync(trace, service.ExecuteAsync, new ReplayOptions
{
    LiveToolSteps = true,
    StepRules =
    {
        ["search"] = new ReplayStepRule { IgnoreOutputFields = { "request_id", "fetched_at" } },
        ["read_portal"] = new ReplayStepRule { ReadsExternalState = true },
    },
});
Assert.True(result.Passed, result.Summary);
```

```python Python
result = await test_sdk.replay_async(trace, service.execute, ReplayOptions(
    live_tool_steps=True,
    step_rules={
        "search": ReplayStepRule(ignore_output_fields={"request_id", "fetched_at"}),
        "read_portal": ReplayStepRule(reads_external_state=True),
    },
))
assert result.passed, result.summary
```

```javascript Node
const result = await testSdk.replayAsync(trace, (ctx) => service.execute(ctx), {
  live_tool_steps: true,
  assertions: [],
  step_rules: {
    search: { ignore_output_fields: ["request_id", "fetched_at"] },
    read_portal: { reads_external_state: true },
  },
});
assert.ok(result.passed, result.summary);
```
</CodeGroup>

A changed output fails with both values:

```
Tool output changed: 'format_price' (recorded step 2) ran with its recorded input and returned "EUR 1250" instead of "EUR 12.50".
```

The agent gets the new output, so the code that parses it runs too.

| Step | In a tool-live replay |
|------|-----------------------|
| `tool` whose input matches its recording | Runs for real. Its output, or its failure, is compared with the recording. |
| `tool` called with an input the recording doesn't have, or never recorded | Stops the replay as inconclusive: there is no recorded output to compare with. |
| `tool` marked `ReadsExternalState` (`reads_external_state`) | Served from the recording and counted as not replayed, never as a pass. |
| `llm` and untyped steps | Served from the recording. |

Outputs are compared as JSON, ignoring key order. `IgnoreOutputFields` (`ignore_output_fields`) drops fields that change on every call, such as ids and timestamps. A tool-live replay in which no tool ran fails, since nothing was checked. `Summary` reports how many tools ran, how many weren't replayed and how many outputs changed. `Fidelity.ToolChecks` (`tool_checks`) lists each comparison. [Faults](/guides/failure-paths) work in a tool-live replay too. A tool-live replay makes no model calls, so `VevalTestSdk` allows it.

### Which tools this covers

Tool-live replay works for tools whose output follows from their input: parsers, formatters, calculations, and lookups against fixed data. It can't check a tool that reads state the recording doesn't hold, such as a live web page, a customer portal, a database, or the clock: running it again returns today's state, not the recorded one. Mark those `ReadsExternalState`, and test them with real runs checked by assertions: `ToolCalled`, `StepExists`, `NoErrors`, `MaxSteps` and `Judge`.

For a scenario, set `LiveToolSteps` (`live_tool_steps`) in `ScenarioOptions` for every trace-backed item, or on one item. It takes precedence over `MockModelSteps`.

## Skip side effects

Only code inside a step is served from the recording. Work your agent does outside a step runs again on every replay, so check `IsReplay` before it. `IsReplay` is true in every replay, mocked or live, and false in a normal run.

<CodeGroup>
```csharp C#
var reply = await ctx.TrackStepAsync("write_reply", slot, handle => WriteReplyAsync(slot, handle));

if (!ctx.IsReplay)
    await email.SendAsync(customer, reply);
```

```python Python
reply = await ctx.track_step_async("write_reply", slot, write_reply)

if not ctx.is_replay:
    await email.send(customer, reply)
```

```javascript Node
const reply = await ctx.trackStepAsync("write_reply", slot, (handle) => writeReply(slot, handle));

if (!ctx.isReplay) await email.send(customer, reply);
```
</CodeGroup>

If the side effect's result matters to the agent, wrap it in a step with `SetMeta("type", "tool")` instead: replay then returns the recorded result without running it.

## ReplayAsync directly

For lower-level control, use `ReplayAsync` with explicit assertions:

<CodeGroup>
```csharp C#
var replayResult = await testSdk.ReplayAsync(
    trace,
    service.ExecuteAsync,
    new ReplayOptions
    {
        MockLlmResponses = true,
        Assertions       = [
            TraceAssert.NoErrors(),
            TraceAssert.StepExists("classify"),
        ],
    }
);

Console.WriteLine(replayResult.Failures.Count == 0 ? "Pass" : "Fail");
foreach (var f in replayResult.Failures)
    Console.WriteLine(f);
```

```python Python
from veval import ReplayOptions, TraceAssert

replay_result = await test_sdk.replay_async(
    trace,
    service.execute_async,
    ReplayOptions(
        mock_llm_responses=True,
        assertions=[
            TraceAssert.no_errors(),
            TraceAssert.step_exists("classify"),
        ],
    ),
)

print("Pass" if not replay_result.failures else "Fail")
for f in replay_result.failures:
    print(f)
```

```javascript Node
import { TraceAssert } from "@veval/sdk";

const replayResult = await testSdk.replayAsync(
  trace,
  (ctx) => service.execute(ctx),
  {
    mock_llm_responses: true,
    assertions: [
      TraceAssert.noErrors(),
      TraceAssert.stepExists("classify"),
    ],
  }
);

console.log(replayResult.failures.length === 0 ? "Pass" : "Fail");
for (const f of replayResult.failures)
  console.log(f);
```
</CodeGroup>

| `ReplayResult` member | Description |
|-----------------------|-------------|
| `Failures` | List of assertion failure messages |
| `ReplayedContext` | The `VevalExecutionContext` from the run |
| `Output` | Return value of your agent |
| `Status` | `"success"` or `"error"` |
| `Error` | Exception message if status is `"error"` |

## LastStatus / LastError

After `RunAsync`, inspect the outcome without catching exceptions:

<CodeGroup>
```csharp C#
await testSdk.RunAsync("my-agent", service.ExecuteAsync);

Assert.Equal("success", testSdk.LastStatus);
Assert.Null(testSdk.LastError);
```

```python Python
await test_sdk.run_async("my-agent", service.execute_async)

assert test_sdk.last_status == "success"
assert test_sdk.last_error is None
```

```javascript Node
await testSdk.runAsync("my-agent", (ctx) => service.execute(ctx));

expect(testSdk.lastStatus).toBe("success");
expect(testSdk.lastError).toBeNull();
```
</CodeGroup>
